## Objetivo e situação atual

O proprietário determinou que toda tarefa deve ser classificada e acompanhada por Issue, branch e PR. O fluxo anterior incluiu publicações diretas; a nova regra passa a valer para as próximas entregas.

## Escopo

- Atualizar AGENTS.md com o padrão obrigatório para qualquer agente/modelo.
- Adicionar modelos de Issue para os três tipos e um modelo de PR com todos os campos exigidos.
- Organizar o backlog sem duplicar Issues existentes.

## Critérios de aceite

- [ ] Contexto e modelos versionados em um PR relacionado a esta Issue.
- [ ] Todas as tarefas planejadas registradas no GitHub com a classificação correta.
- [ ] Descrições dos PRs incluem Issue, mudanças, validação, riscos, limitações e próximos passos.

## Validação prevista

Revisar os documentos e os modelos; verificar os links e a correspondência entre backlog e GitHub. Não exige deploy da aplicação.

## Dependências e bloqueios

A API api.github.com está bloqueada pela rede do ambiente. A inclusão do domínio foi salva em rascunho; ainda precisa ser aplicada. O acesso Git de leitura funciona, mas isso não comprova acesso à API.

## Entrega por Pull Request

Vincular o PR a esta Issue e registrar mudanças, validação, riscos, limitações, próximos passos e estado do deploy, conforme AGENTS.md. Não usar `Closes` enquanto o aceite operacional estiver pendente.
