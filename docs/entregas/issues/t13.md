## Objetivo e situação atual

Ao integrar os commits recentes de main, o bun.lock passou a apontar para o cache `europe-west1-npm.pkg.dev`. O instalador existente substitui apenas o prefixo `europe-west4-npm.pkg.dev`; a instalação congelada falhou com HTTP 403 no novo cache. Isso impede reproduzir a instalação e pode bloquear builds na Vercel.

## Escopo

- Suportar os prefixos regionais de cache realmente usados pelo lockfile, por meio de uma cópia temporária com URLs do registry npm oficial.
- Preservar versões, hashes de integridade, TLS, package.json e bun.lock.
- Manter o Bun fixado e a instalação frozen-lockfile; não ampliar exceções de idade de publicação.

## Critérios de aceite

- [ ] Instalador oficial funciona com o lockfile atual e com os prefixos regionais conhecidos.
- [ ] Manifesto e lockfile versionados permanecem byte a byte inalterados pela instalação.
- [ ] Falhas de instalação preservam o status de saída e removem o staging temporário.
- [ ] Build é validado com a instalação oficial corrigida.
- [ ] Correção entregue em PR separado e vinculado a esta Issue.

## Validação prevista

Reproduzir o erro no instalador atual; testar o ajuste com o lockfile congelado e conferir o diff. Um helper temporário fora do checkout permitiu validar o registry público mantendo os hashes; isso não constitui correção do instalador versionado.

## Dependências e bloqueios

Depende de T01 (identificador local, a substituir pelo link real). A API GitHub está bloqueada. Não implementar a correção versionada antes de criar a Issue. T02 pode ser preparado como draft, mas não deve ser considerado pronto para novo deploy enquanto esta dependência persistir.

## Entrega por Pull Request

Registrar a Issue, a diferença de comportamento, os resultados de instalação/build, riscos, limitações, próximos passos e a reversão. Não modificar os locks para contornar o bloqueio.
